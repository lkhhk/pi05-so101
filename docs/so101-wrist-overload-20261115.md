# SO-101 腕部过载排查与坐标居中

## 已观察到的故障

最初故障快照：从臂 wrist_flex 目标 982、实际 3877，Torque_Enable=1、Status=32，SDK 解码为 Overload。其余五个关节无故障但保持力矩开启。经用户确认托稳后关闭六个电机力矩，故障状态清零，用户确认可以手动活动。

原遥操作循环只限制每次指令变化，没有检查目标与实际位置的累计偏离。使用上述目标/实际快照重放时，原代码仍发送目标；新增回归测试先失败，修改后通过。不在真机上主动重现过载。

## 手工只读测量与新校准

用户在力矩关闭时确认：中间姿态 745，一侧舒适边界 1865，另一侧边界 3909。相对于中间姿态展开后，连续区间为 -187..1865，跨度 2052 ticks，跨过原编码器零点。

只调整从臂 wrist_flex：

| 项目 | 原值 | 新值 |
| --- | --- | --- |
| Homing_Offset | -413 | -1715 |
| Min_Position_Limit | 1 | 1115 |
| Max_Position_Limit | 4095 | 3167 |

旧坐标加 1302 后成为新坐标，原中间姿态变为 2047；其他五个关节的校准保持原值。旧 IK 的腕部几何参考通过 `so101_coordinates.wrist_zero` 随 homing offset 一起平移，避免继续使用固定 876。它保留旧几何约定，不代表重新验证了 URDF 的精度。

最终成功备份与写入记录：`backups/so101-wrist-recenter-20261115-132926-197057/`。文件和硬件已匹配，用户随后断开并重接从臂电机电源。

## 校准过程中的异常与纠正

前两次校准写入遇到损坏/残留应答及回滚确认失败，随后逐项读取、恢复原寄存器，再更换为逐项写入、等待、清理残留应答、完整响应长度校验及读回的方式。

一次恢复操作将当前位置写入 Goal_Position，错误地假定关闭力矩时这不会启动电机。随后仅 wrist_flex 出现 Torque_Enable=1 和过载；已立即关闭腕部力矩。此假设已纠正：校准工具已移除所有位置目标写入，不以写目标作为校准预装步骤。最后一次成功校准的 `position_goal_writes` 为 0，所有电机力矩保持关闭。

上游问题记录报告了相同类型的风险，但不能仅凭这些记录断言本机最初故障的唯一原因：

- https://github.com/huggingface/lerobot/issues/3585 ：Goal_Position 写入可能自动开启力矩、范围与实际目标可能不一致。
- https://github.com/huggingface/lerobot/issues/5324 ：跨零点后的内部圈数可能在正常位置读数下被隐藏，重新写校准不能清掉，断开电机电源后可清除。

## 控制程序修改与验证

- 启动前检查全部关节位置、腕部有效范围和位置稳定性，再发送第一条目标；把目标写入视为可能立即使电机出力的操作。
- 腕部靠近已测边界时拒绝启动，允许在电机关闭状态下先回中间姿态。
- 每个控制步先验证所有关节，任一当前目标或拟下发目标偏离实际超过 64 ticks 时停止，避免向前几个关节发完后才发现后面的关节有问题。64 ticks 是保守的软件停机阈值，不是经过认证的安全限值。
- 保持操作只对已经开启力矩且无读取故障、实际位置仍在范围内的关节下发当前位置，避免将原本关闭的关节自动启动；单关节故障不阻止其他已开启关节更新保持。
- 窗口加入“已托稳从臂：解除电机保持”按钮，逐个关闭并读回六个力矩开关。录制期间使用此按钮会先将当前示范标记无效。
- 12 项无硬件测试通过，包括故障快照、开始前完整预检、暂停无写入、已关闭关节不被保持动作启动、单关节故障隔离、坐标平移不改变既有 IK 角度，以及校准入口不写位置目标或开启力矩寄存器。

断电重启后的只读核验：`results/so101-after-wrist-recenter-20261115-133118.json`。六个电机均 Torque_Enable=0、Status=0，硬件校准与文件一致；主从臂通信和两路相机检查通过。重新打开暂停窗口后，用户按要求进行了腕部小幅实机跟随检查，并反馈“小幅跟随正常，方向一致”。这验证了修改后的该次小幅跟随，不代表整个活动范围或完整任务均已验证。

## 后续按用户要求移除软件限速和跟踪偏差停机

用户反馈正常操作会触发 64 ticks 停止，并明确不需要约 22°/秒的限速。已删除 250 ticks/秒的目标追赶逻辑和两处 64 ticks 停机检查，目标直接按主臂相对增量更新。保留实际校准范围、输入跳变、通信超时、电机故障停止，以及开始前的完整姿态检查。上文 64 ticks 保护是历史修改记录，不再代表当前行为。

当前 15 项测试通过，新增验证直接下发目标不受旧限速影响、超过 64 ticks 的正常滞后不再停止、实际关节范围仍生效、电机故障仍在发送动作前停止。已保存故障快照在新腕部范围外，仍会因实际位置超出范围被拒绝，而非触发已删除的跟踪误差阈值。此修改未向真机发送运动指令，重启采集窗口后生效。
