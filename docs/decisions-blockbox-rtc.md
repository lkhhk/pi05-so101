# 方块入盒远程 RTC 接入决策

2026-11-17，用户选择并授权实施方案 B：优化传输 + 异步执行 + LeRobot guided RTC。

约束为现有 Windows / COM6 / SO-101、本机相机采集、云端 RTX 4090 推理，继续使用 IRA 底座上的 020000 LoRA；身体关节角度、夹爪百分比、录制校准和 front/wrist 顺序保持一致。

选择理由：同步推理实测请求平均 1.817 秒，超过 50 帧在 30 Hz 下的 1.667 秒覆盖时间；单纯并行预取不能保证跨块衔接，采用已有官方 guided RTC，避免自行实现去噪引导算法。本模型未做训练式 RTC，使用 inference-time guided 模式。

实现使用独立服务端口 8092，保留同步端口 8091。复用训练同版云端 LeRobot 的 RTCProcessor、客户端安装版本的官方 ActionQueue。通过模型空间的剩余动作、实测延迟与消费游标对齐下一块，不将电机角度直接当作归一化前缀。

图像先按模型 bilinear/align_corners=False 缩到 168×224，PNG 传输；服务器恢复原模型 float padding=-1。插值结果量化带来的输入误差上界约 0.5/255，不改变 RGB 顺序、长宽比或背景边框值。HTTP 长连接仍通过 SSH 回环端口转发。

启用模型的 RTCConfig 后使用 torch.no_grad 而非 torch.inference_mode，保留官方 RTC 内部梯度引导能力。服务端在预热及有前缀请求中验证 10 个去噪步骤实际进入 guidance。

不增加运动速度限制，保留校准物理范围。客户端按实测完整请求时间验收队列预算；过期回复、前缀耗尽、错序/部署不符或队列欠载会停止发送动作，不重播旧动作。Esc/正常结束保持当前测得位置；通信异常无法保持时尝试关闭力矩。

执行准入比“延迟小于 50/30 秒”更严格：请求消耗一部分新预测时间轴，下一次请求还需要时间，因此要求 2×(ceil(实测延迟×30)+2)+4 < 50，并有足够的剩余前缀。最终以无电机时序测试和每次执行前的网络预检为准。

实现文件：`scripts/blockbox_rtc_protocol.py`、`scripts/blockbox_rtc_queue.py`、`scripts/serve_blockbox_rtc.py`、`scripts/run_blockbox_rtc.py`；回归检查 `scripts/test_blockbox_rtc.py`。

实施结果：8 项回归检查通过；保存观测和真实观测只读测试各 30 秒、900 个周期、59 次补充、0 次队列断供、0 帧电机动作命令。真实观测测试 guided 完整请求平均 0.344 秒、P95 0.435 秒、最大 0.516 秒，均通过客户端预检和连续队列验收。使用方法与证据见 `docs/so101-block-box-rtc-20261117.md`。
